## A. Принципы и остановка испытаний

- **Рабочую базу никогда не использовать для теста.** Для Linux применять отдельный `XDG_DATA_HOME`; для Windows — изолированный тестовый профиль или VM с доказанно отдельной базой. Когда изоляция эталонного Windows R11 не подтверждена, изменяющие тесты на нём запрещены.

- Эталон — подтверждённое поведение **Windows R11**, а не старой R3/R9. Если документы или версии правил противоречат друг другу, сравнивать безопасный Windows R11 на одинаковых данных и документировать расхождение. В частности, позднее правило R11: простые положительные часы и `1/N` → дневная смена; `2/N` → ночная; `В/ДП/ОТ/0/пусто` → без смены. Исторический документ `TAB2_RULES.md` даёт старое правило для простых часов.
- **Отдельная «разукрашка»** не считается уже готовой частью исходного R11 Core. Её эталон — действующий Windows Excel-инструмент с согласованной логикой; перенос и приёмка — отдельные обязательные испытания.
- Зелёный GitHub CI или HTTP 200 проверяет только протестированные сценарии, не подтверждает правильность расчётов.

**Критичность:** P0 — потеря данных, изменение чужого сотрудника, неправильные часы/закрытие без предупреждения, доступ к рабочей базе; P1 — ошибка цикла/секции/импорта/редакций/РВД, блокирующая работу; P2 — существенный UX/скорость; P3 — косметика. Это независимая от текущей сессии схема воспроизведения, исходные PNG можно найти по таблице выше. При иных размерах исходных кадров **пересчитать координаты**, а не переносить без проверки. Параметры в скрипте: `BLUE='#1248D3'`, `AMBER='#B86200'`, `RED='#C32828'`, `G=72`, `R=32`, `TOP=25`, `BOTTOM=64`. В итоговом HTML изображения встроены в `data:image/png;base64`, без внешних сетевых файлов. В Word изображения вставлены в фиксированном порядке и масштабированы пропорционально.

**Критерий брака:** рамка закрывает текст, задевает соседнюю кнопку, сливается с соседней рамкой, номер указывает на другой элемент, скриншот содержит придуманный элемент, при увеличении не видно текста, либо пояснение предписывает действие, которого нет на данном экране. При любой такой ошибке **исправить до отправки**.

## C. Обязательное правило достоверности текста инструкции

**Нельзя писать «нажмите кнопку "Прочитать файл заново"»**: такой кнопки в предварительном просмотре нет.

После ошибок импорта реальная последовательность: **«Отмена» → исправить и сохранить исходный файл XLSX/CSV → «Выбрать файл» → «Прочитать файл» → повторно проверить счётчики.**

Почему: экран предпросмотра хранит считанные данные; изменение Excel на диске не обновляет их автоматически. Повторное чтение нужно **только при исправлении файла**; если изменений нет — читать ещё раз незачем. Не добавлять в справку двусмысленные предложения или непроверенные действия.

В интерфейсе экспериментальной ветки пояснение обновлено, но в старом снимке `excelerrors.png` показан прежний текст. Не подменять исходный снимок; в подписи честно указывать, что текст на старом снимке относится к предыдущей сборке. Когда будет скрин новой сборки, заменить **только этот** снимок.
