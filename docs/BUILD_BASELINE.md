# Исходная проверка сборки LaborControl

**Дата:** 20.11.2026  
**Источник:** оригинальные Go-файлы из `archive/controller-r9/`, без исправлений.  
**Среда проверки:** отдельная временная Linux-среда ChatGPT, Go 1.23.2 linux/amd64. **Это не виртуальная машина пользователя с Альт Linux.**

## Команда Linux

```bash
go test ./...
```

Результат: **ошибка компиляции**, до запуска тестов дело не дошло.

Примеры из вывода компилятора:

```text
./main.go:82:12: undefined: openURL
./main.go:83:6: undefined: showMessage
./main.go:95:2: undefined: terminateStaleCoreProcesses
...
FAIL laborcontrol_full_preview [build failed]
```

Причина: `platform_windows.go` помечен `//go:build windows` и содержит эти функции только для Windows. Linux-вариант платформенного файла отсутствует. Это **не означает**, что остальные модули уже проверены.

## Проверка Windows-компиляции

```bash
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go test -c -o /tmp/controller_r9_tests_windows.exe
```

Результат: **успешная кросс-компиляция** тестового бинарника (`BUILD_OK`). Тестовый бинарник Windows в этой Linux-среде **не запускался**, следовательно прохождение тестов **не подтверждено**.

## Следующие действия

1. Создать отдельную рабочую папку Linux-порта. Не менять исторические исходники в `archive/`.
2. Добавить Linux-адаптеры запуска браузера, сообщений, управления процессами и путей хранения данных.
3. Не считать собранный контроллер полнофункциональной R11: актуальные исходники Core v0.9.11 отсутствуют.
4. Подготовить изолированные тестовые данные и позже проверить запуск в VirtualBox с Альт Linux.
