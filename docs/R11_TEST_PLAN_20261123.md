## Инцидент после удаления выбранного сотрудника (22.11.2026)

Пользователь удалил сотрудника, который был выбран в АвтоГрафе. После обновления состояния `agTab` сохранил уже отсутствующий табельный номер. `ensureAgDefaults()` исправлял только пустой выбор, но не устаревший; `autografGraph()` затем вызывал расчётные функции с `agEmployee() === undefined`, что приводило к `undefined is not an object (evaluating 'e.hire_date')`. В экспериментальной ветке исправлено: выбор проверяется по актуальному списку сотрудников, при удалении выбранного сотрудника выбирается оставшийся (311267, если есть, иначе первый), сбрасываются архивный предпросмотр и зависимые временные состояния; рендер графика имеет дополнительную защиту. Добавлен Node smoke-тест сценария с удалённым выбранным табельным номером и устаревшим архивным предпросмотром. CI и ручная проверка на ALT отмечаются отдельно. Резервная копия перед удалением автоматически создаётся в `~/.local/share/LaborControl-R11-Desktop-Experimental/LaborControl/backups/` (если не задан `LABORCONTROL_DESKTOP_DATA_HOME`). Само удаление намеренно удаляет связанные записи сотрудника, поэтому восстановление выполнять только из копии и по запросу пользователя.

## Повторная ревизия кода вкладки «Сотрудники» — 22.11.2026

**Исходники:** `port/controller/r11_original.html`, `port/controller/frontend.html`, `port/controller/r11_core.go`, `port/controller/r11_input_validation.go`, `port/controller/r11_point_template.go`, `port/controller/r11_xlsx.go`. **Код сборки:** `b781213bda0c008cabef274a9dbf86a5b0617fd2`. Внесено **только в экспериментальную ветку**, main/Windows-база не менялись.

**Обнаружено и исправлено:**

1. Массовый импорт сотрудников и пунктов сбора выполнялся последовательными запросами, мог оставить частично обновлённую базу при ошибке в середине. Добавлен атомарный POST `/api/employee/batch`: сначала проверяются все карточки, сохранение и резервная копия — единой операцией; при ошибке нет частичного изменения.
2. Кнопка «Изменить» включала неэкранированный JSON сотрудника прямо в HTML-атрибут. Теперь использует цифровой ID и находит актуальную карточку; ФИО с апострофом не нарушает интерфейс.
3. При ошибках в XLSX/CSV кнопка импорта была `disabled` без явного объяснения. Добавлено видимое пояснение «Импорт недоступен…» и стилизация.
4. Предыдущий CSV-парсер неверно разбирал переносы строк внутри кавычек. Реализован разбор экранированных кавычек, разделителей и многострочных полей; незакрытая кавычка вызывает явную ошибку.
5. Локальная запись истории `uiAudit` могла создаваться до успешного ответа сервера на сохранение карточки. Перенесена после успешного API-ответа.
6. Проверка корректности дат/ФИО в шаблоне и блокировки ошибочного импорта выровнена в обеих встроенных версиях интерфейса.
