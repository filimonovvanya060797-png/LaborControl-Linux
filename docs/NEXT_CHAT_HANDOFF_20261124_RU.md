## Процесс работы — обязательные правила

1. Не начинать проект заново и не переспрашивать известные решения. Проверить PR #34, issues #33/#28/#26/#16 и актуальную ветку. Различать код, CI, ALT-проверку; issue не закрывать по одному зелёному CI.
2. Только тестовая/синтетическая база, backup до миграций и массовых изменений. Нельзя рисковать реальными водителями/табелями или менять историю/записанные графики молча.
3. Автоматизировать тесты самостоятельно: Go unit/API, JS, настоящий GTK/WebKitGTK smoke и CI. Пользователь проверяет ТОЛЬКО то, что без ALT нельзя доказать.
4. Один шаг — один тест — максимум один реально нужный скриншот. Пройденные тесты больше НЕ повторять. В GitHub фиксировать PASS_ALT_SCREENSHOTS / PASS_ALT_USER / FAIL_ALT / BLOCKED / NOT_RUN с точным объёмом доказательств и новыми кадрами для #16.
5. Интерфейс должен быть простым новичку: сначала устранять сложный UX, а не писать длинные инструкции к неудобству. Русский язык, понятные подписи, ввод даты ДД.ММ.ГГГГ с автоматическими точками, календарём и очисткой. Ручные нестандартные настройки сворачивать.
6. Для инструкции использовать ТОЛЬКО реальные скриншоты LaborControl: стиль V7 — чёткие ровные контрастные нумерованные рамки без перекрытий, синий действия, красный ошибки, оранжевый предупреждения; читать в масштабе. Пользователь присылает снимки без разметки, ассистент выбирает кадры/нумерует/размечает; уже полученные не запрашивать повторно. Полностью по-русски, встроенная офлайн-справка. Интерактивное обучение с подсказками и достижениями позже после функциональной эквивалентности Windows R11.
7. Приоритет продукта: максимально точный перенос работающего Windows R11 на ALT Linux, один техник/две колонны/~450 водителей; АвтоГраф, табели, «разукрашка» Excel, ИСАТ/SAP, больничные, командировки, нормы, редакции/план-факт, РВД. Сначала паритет и сохранность, затем расширение.
