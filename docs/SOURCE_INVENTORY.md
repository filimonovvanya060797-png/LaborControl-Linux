# Инвентаризация исходников LaborControl

**Дата фиксации:** 20.11.2026

## Классификация

- `archive/controller-r9/` — оригинальные исходники контроллера R9 (Go, HTML, тесты, Tab2). `main.go` содержит `controllerVersion = "v1.0-TIMESHEET-PREVIEW-R9"` и использует `LaborControl_Core_R9.exe`. **Это не исходный код полной R11.**
- `archive/legacy-v0.3/` — историческая основная программа v0.3, только для анализа; не является актуальным Core v0.9.11.
- `archive/browser-shim/` — отдельная минимальная заглушка браузерного запуска, два файла.
- `archive/build-scripts/` — оригинальные Windows/PowerShell скрипты, включая `make_linux.ps1`. Скрипт Linux предполагает наличие Core-исходников, которых в комплекте нет.
- `docs/reference/` — переданные документация, правила Табеля, история сборок, статусы исходников и SHA256 для оригинальных бинарных релизов.
- `docs/PROJECT_HANDOVER.md` — текущий паспорт проекта и журнал передачи контекста.

## Исключено из репозитория

- `LaborControl.exe`, `LaborControl_Core_R11.exe`, `rundll32.exe` — оригинальные Windows EXE, не публикуем и не используем в качестве Linux-сборки;
- `ProductionCalendar_2028.xlsx` — бинарный образец календаря, хранится вне репозитория до проверки содержимого;
- рабочие базы `labor_control.json`, `labor_control_tab2.json`, папки резервных копий — не загружаем;
- снимки экрана, локальные временные файлы;
- `frontend_v0_9_11_TIMESHEET_R9.html` — побайтово совпадает с `archive/controller-r9/frontend.html` (SHA256 10538789e8ede51950070867adf7e947d6c3add8b1112852ad368a443a15a29e).

## Нерешённые технические вопросы

1. Актуального исходного кода `LaborControl_Core_R11.exe` / backend v0.9.11 **нет**. Его поведение предстоит документировать и восстанавливать без предположения, что старый Core v0.3 эквивалентен.
2. Версия R11 расширяет R9: привязка вида графика к конкретному циклу полётов; обычные положительные часы обозначают дневную смену. При переносе применять правила R11, а не слепо переносить дефекты R9.
3. Исходные файлы сохранены отдельно от будущих Linux-исходников. Перенос будет идти в новой рабочей папке, без перезаписи архива.

## Следующий шаг

Подготовить рабочий Linux-проект с независимым платформенным слоем, тестами `go test` и компиляцией контроллера без Windows-specific API; затем восстанавливать недостающий Core и UI R11. Запускать всё на синтетических данных, в отдельной папке виртуальной машины Альт Linux.
