## Главное различие действий

1. **Предварительный расчёт**: изменение только локального черновика; «Отменить расчёт» удаляет предварительный результат, не вносит рейсы/отпуска/дни графика в базу.
2. **Сохранить/записать**: подтверждённый запрос к серверу, потенциально серия операций и контрольная копия. Не называть отменой предпросмотра.
3. **Удалить сохранённое**: отдельная опасная операция с подтверждением; может не возвращать автоматически уже записанные графики работников.
4. **Восстановление версии**: отдельное действие для графика сотрудника (не все сущности поддерживают версионирование). Не обещать универсальный Undo, которого сейчас нет.

## Выявленные сквозные сценарии, защищённые в пакете

- Поля даты: универсальный ручной ввод `ДД.ММ.ГГГГ`, автоточки, календарь, крестик `×` уже реализованы в предыдущей ветке (#22).
- Выбор пункта сбора из имеющихся справочников и сотрудника без предварительной записи нового маршрута — исправление #24.
- После предпросмотра цикла не пропадают исходные даты; прежний рассчитанный вариант нельзя сохранить после их изменения.
- Для предпросмотра отпуска и Конструктора — явная отмена и защита от устаревших данных.
- Форма полёта и справочника видов графиков различает создание и изменение; отмена редактирования сбрасывает ID.
- При массовом добавлении дат программа требует подтверждения перед немедленной записью (отдельного предпросмотра списка пока **нет**).
- Кнопки изменения/удаления полёта используют числовой ID, а не JSON/строки из данных пользователя в `onclick`; безопасны для названий с кавычками и апострофами.

## Известные ограничения и задачи после первого CI

1. **Нет универсального транзакционного «Отменить последнее действие»** для нескольких вызовов API. Серийное сохранение/удаление цикла может частично завершиться при сетевом сбое; нужен отдельный дизайн транзакций и восстановления до промышленного внедрения. Не решать косметической кнопкой.
2. Ввод нескольких дат в «Быстро добавить» пока использует непосредственный запрос после подтверждения; для массовых изменений разумен отдельный предпросмотр и отчёт о дублях.
3. «Очистить производственный календарь» удаляет много данных; прежде чем давать возможность «Отменить», нужен гарантированный путь резервного восстановления. Сейчас есть подтверждение, но нет мгновенного отката.
4. Эталонная сверка с Windows R11 и 28-дневного общего цикла по конкретным направлениям отдельно не проведена; расчётные правила без бизнес-подтверждения не менять.
5. Не проверены стресс-сценарии реальных 450 сотрудников с большим количеством одновременно открытых редакций и нештатные обрывы во время массовой записи.

## Приёмочный пакет без повторения старых тестов

**CI:** статический JavaScript-аудит, существующий R11 UI smoke, новые проверки дат/отмены/сохранения полей/режима редактирования/кавычек, Go регрессия, сборка GTK, настоящий WebKitGTK UX smoke. **Обязательно сверить SHA с архивом.**

**ALT Linux:** после успешного CI и резервной копии учебной базы — один комплексный пользовательский сценарий: открыть согласованные полёты, ввести реальные учебные ДП Тюмени, получить предпросмотр, нажать **«Отменить расчёт»**, убедиться, что даты остались в полях, и вновь построить. Далее отдельным сеансом проверить сохранение и управляемое удаление *только* синтетического цикла, затем виды графиков → Конструктор → отмена предпросмотра. Не запрашивать старые скриншоты принятого ограничения увольнения.

**Инструкция #16:** после принятия сделать 1–2 реальных русскоязычных кадра нового интерфейса, обозначить 3 разных действия (отмена предпросмотра, запись, удаление сохранённого), сохранить стандарт V7 рамок/нумерации. Файлы PNG в исходниках инструкции пока не добавлены.
