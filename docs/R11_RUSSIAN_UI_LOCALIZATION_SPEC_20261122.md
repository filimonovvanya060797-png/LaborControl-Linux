# Техническое задание: полная русификация интерфейса LaborControl R11 на ALT Linux

**Дата:** 22.11.2026. **Основание:** пользователь увидел на странице выбора Excel-файла английскую надпись `no file selected` рядом с русской кнопкой «Выбрать файл» и потребовал, чтобы **все видимые надписи программы были на русском**.

**Статус:** частичная реализация в экспериментальной ветке от 22.11.2026. Общий русскоязычный выбор файлов добавлен в R11, Tab2 и страницу состояния; сохранены исходные ID, accept и обработчики, поддерживается динамическая перестройка экранов. В GTK реализованы русские диалоги alert/confirm/prompt. Добавлены Go/Node тесты. **Проверка новой сборки в пользовательской ALT Linux и полный аудит всех ошибок пока не завершены.** Рабочая Windows-база и существующие данные пользователя не затрагиваются.

**Ветка для будущих исправлений:** `fix/r11-ux-and-employee-20261122`. Область — основной R11, встроенный Tab2, вспомогательная страница импорта/восстановления, GTK/WebKitGTK-оболочка, документация и будущий учебный центр.

## 1. Главный принцип

Любой **текст для техника**, который появляется в интерфейсе или в сообщении об ошибке, должен быть на **простом правильном русском языке**. Это включает заголовки, меню, кнопки, подсказки, состояния, формы, выбор файлов, предупреждения, подтверждения, надписи окон, результаты операций, текст поиска и инструкций.

**Не переводить и не менять машинные значения/контракты:** имена файлов, расширения `.xlsx`, `.xlsm`, `.csv`, `.json`, названия систем `SAP`, `ИСАТ`, `ALT Linux`, `LaborControl`, структурные имена колонок входного CSV (например, `tab_no`), поля JSON/HTTP API, базы, флаги и служебные статусы. Если технический код виден пользователю, рядом дать русское человекочитаемое объяснение, сохранив код в данных.

Не менять формулы, графики, расчёты, схему БД и переносимость Windows R11 ради перевода интерфейса.

## 2. Немедленная проблема: «no file selected»

**Сейчас:** стандартный `<input type="file">` показывает русскую кнопку и английское системное сообщение `no file selected` — это часть интерфейса WebKit/Chromium, а не переводимая строка нашего JS.

**Требуется:** единый компонент выбора файла, у которого **отображаемый** текст полностью контролирует LaborControl:
- исходное состояние: кнопка «Выбрать файл», подпись «Файл не выбран»;
- файл выбран: «Выбран файл: *исходное имя файла*»;
- после отмены системного окна: «Файл не выбран» (либо сохраняется прежний выбор, если он действительно остался);
- если пользователь выбрал новый файл: имя обновляется;
- после сброса формы: «Файл не выбран»;
- при ошибке формата: «Неподдерживаемый формат файла. Выберите файл XLSX или CSV» с корректным набором расширений по конкретной форме;
- у кнопки загрузки/проверки файла должны быть русские подсказки: «Прочитать файл», «Проверить шаблон», «Загрузить файл» по назначению.

**Техническая реализация:** видимая русская кнопка + текстовое поле-статус; настоящий `input[type=file]` остаётся в DOM и продолжает использовать **исходный ID, атрибут accept, событие change и передачу файла в API**. Обновлять видимый статус через `textContent`, а не `innerHTML` (имя файла недоверенное). Обеспечить кнопку через `label[for]` или прямое действие пользователя, работу с клавиатуры/экранным считывателем и объявление изменения статуса через `aria-live`. Не полагаться на автоматическую локаль браузерного движка. Не пытаться «перевести» браузерную строку CSS; полностью скрыть нативный визуальный элемент с сохранением доступного выбора файла.

## 5. Диалоги подтверждения и сообщения об ошибках

**Подтверждения.** В `r11_original.html` найдено множество вызовов нативного `confirm()` (в исходнике 44 текстовых вхождения), аналогично в `frontend.html` (47 вхождений). Часть операций уже переведена на собственные русские диалоги в PR #15, **но это ещё не полный переход**. Проверить все оставшиеся рабочие вызовы `confirm()`, `alert()`, `prompt()`, включая редкие и аварийные ветки, а также вспомогательные страницы.

Для опасных действий желателен диалог со смысловым названием:
- Заголовок: «Удаление сотрудника».
- Текст: «Удалить сотрудника №…? Связанные записи графика также будут удалены».
- Кнопки: «Отмена» и «Удалить».
- Отмена, клавиша Esc, закрытие окна не должны выполнять действие.

**Возможные английские ответы сервера.** В Go API присутствуют `GET only` / `POST only` и другие служебные сообщения. Не менять API-методы и коды ошибок. При попадании этих текстов в интерфейс показать понятное русское объяснение, сохранив оригинал в диагностических логах. Проверить `r11_core.go`, `main.go`, обработку `fetch`-ошибок и HTTP-ответов.

**Встроенная GTK-оболочка.** В `port/desktop/main.c` кнопки диалога сохранения уже определены строками `_Отмена` и `_Сохранить`; проверить на реальной установленной ALT Linux версии, что заголовок и остальные кнопки/подсказки действительно по-русски. Системное `GTK_BUTTONS_CLOSE` требует проверки локали. Системные окна файлового менеджера могут зависеть от языка ОС: там, где диалог контролируется программой, задавать явные русские заголовки/кнопки; пользователь должен понимать действие даже если окружение использует другую локаль.

## 6. Технические правила реализации

1. Отдельный словарь русских UI-строк или единые функции надписей вместо множества рассыпных фрагментов; один термин — один перевод во всех разделах.
2. Везде HTML `lang="ru"`, корректный UTF-8. Подписи `label`, `aria-label`, `title`, `placeholder` и альтернативные тексты изображений — на русском.
3. Даты выводить в понятном русском формате `ДД.ММ.ГГГГ`, сохраняя API-хранилище `YYYY-MM-DD`. Не подменять временные зоны и расчёты.
4. Числа/единицы измерения и названия статусов использовать согласованно; кодовые значения графиков (например `ДП`, `1/11`, `2/11`) не менять.
5. Текст ошибок должен отвечать: **что не получилось**, **почему**, **что исправить**. Избегать сообщений «Error» и HTTP-терминов без объяснения.
6. Кнопка или ссылка «Инструкция» в сложной форме должна открывать соответствующую главу; одинаковые формулировки инструкции и UI.
7. Не строить локализацию простым поиском и заменой английских слов во всех исходниках: это может сломать JSON-поля, JavaScript, пути, тесты, формат импортов и совместимость Windows R11.
8. Повторно проверить все упомянутые функции в GTK и в Chromium GOST; визуальной замены недостаточно.

## 8. Приоритет и готовность

- **Приоритет P1 (ближайшая доработка):** все 12 полей загрузки, реальные статусы файла и самые частые подтверждения/ошибки. Это напрямую устраняет проблему, показанную пользователем.
- **Приоритет P2:** полный обход экранов и системных диалогов, унифицированный словарь, редкие ошибки и вспомогательные формы.
- **Приоритет P3:** проверка соответствия текстов встроенной справке и будущим учебным упражнениям/достижениям.

**Готовность:** ни один активный путь работы техника не показывает английское сообщение, за исключением согласованных машинных обозначений, названий файлов и внешних системных окон, не управляемых LaborControl; выбранный файл корректно обрабатывается; все проверки RU-01..14 пройдены в GTK и Chromium GOST; исправления не меняют расчёты, импорт и данные.
