## Правила

1. Исследовать текст соответствующего исходного файла из GitHub в указанной ветке, запоминать SHA проверенной версии и диапазоны строк. Перед окончательной приёмкой повторно проверять SHA, если файл менялся.
2. Для каждого файла проверить назначение, все функции и ветви обработки ошибок, ввод/вывод, сохранение состояния и безопасность; отдельно выполнение тестов и интеграцию с соседними файлами.
3. Статусы: `REVIEWED_STATIC` (каждая строка прочитана/осмыслена, без утверждения об отсутствии всех ошибок), `TESTED_CI`, `TESTED_ALT`, `FINDING`, `PENDING`. Только конкретно подтверждённые дефекты переводить в `BUG_CONFIRMED`.
4. Не менять программную бизнес-логику без согласования с пользователем. Проверки и результаты фиксировать сразу в этой ветке; не обращаться к рабочей Windows-базе.
5. Обязательно выделить: сохранность/атомарность, кадровый импорт, АвтоГраф, графики/полёты, календарь/балансы, редакции, Табель 2.0, SAP/ИСАТ, перенос «разукрашки», GTK, обновление приложения и инструкции.

## Первая партия — проверенные места

- `main.go:82-112`: запуск desktop отдельно от браузерного режима; запрещён второй desktop процесс при занятом 8779. Автоматическое завершение старого контроллера происходит в другом режиме; нельзя запускать несколько разных экземпляров с одним профилем.
- `main.go:157-179`: маршруты изолированного HTTP-сервиса, внешний middleware `r11LocalOnlyHandler`, сокет `127.0.0.1:8779`; `ReadHeaderTimeout=5s`.
- `r11_http_security.go:13-54`: белый список адресов localhost, запрет сторонних Origin, `Sec-Fetch-Site: cross-site`; имеющиеся регрессионные тесты покрывают основные недоверенные варианты.
- `main.go:789-823`: `makeBackup` использует `O_EXCL`, `0600`, `Sync` и закрытие; `atomicWrite` пишет временный файл на том же ФС и выполняет `os.Rename` без удаления целевого каталога при ошибке. Проверка устойчивости при внезапном отключении питания и `fsync` каталога после rename — отдельное исследование, не зарегистрированный баг.
- `main.go:860-879`: встроенная иллюстрированная инструкция `/help/employees` локальная, GET-only, отключает кэш и запрещает чужие iframe через SAMEORIGIN.
- `install-user.sh:1-31`: установка в `~/.local/opt/LaborControl-R11-Experimental` и ярлык в `~/.local/share/applications`; папки пользовательских данных скрипт не удаляет.
- `r11_input_validation.go`: наличие функций строгой проверки строк, логических значений, часов, полей сотрудника, дней, календаря и строк снимка редакции; их поведение исследовать дальше с негативными кейсами.

### Наблюдения, требующие проверки, не подтверждённые ошибки

1. `main.go:813-822`: после `os.Rename` отсутствует синхронизация родительского каталога. Это возможный риск восстановления после отключения питания на некоторых файловых системах, но не установленная потеря данных. Исследовать переносимость и возможности безопасного теста на временном профиле.
2. `install-user.sh`: сценарий обновления поверх **запущенного** бинарника отдельно не проверен. Установка по инструкции должна проводиться после полного закрытия LaborControl; не трогать работающую тестовую базу при исследовании.
3. У `main.go` 902 строки; для завершения аудита нужны подробная проверка импорта/применения, прокси Core, ошибок конкурентного доступа, логирования и закрытия.
