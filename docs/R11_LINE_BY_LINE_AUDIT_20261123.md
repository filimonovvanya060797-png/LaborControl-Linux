1. Исследовать текст соответствующего исходного файла из GitHub в указанной ветке, запоминать SHA проверенной версии и диапазоны строк. Перед окончательной приёмкой повторно проверять SHA, если файл менялся.
2. Для каждого файла проверить назначение, все функции и ветви обработки ошибок, ввод/вывод, сохранение состояния и безопасность; отдельно выполнение тестов и интеграцию с соседними файлами.
3. Статусы: `REVIEWED_STATIC` (каждая строка прочитана/осмыслена, без утверждения об отсутствии всех ошибок), `TESTED_CI`, `TESTED_ALT`, `FINDING`, `PENDING`. Только конкретно подтверждённые дефекты переводить в `BUG_CONFIRMED`.
4. Не менять программную бизнес-логику без согласования с пользователем. Проверки и результаты фиксировать сразу в этой ветке; не обращаться к рабочей Windows-базе.
5. Обязательно выделить: сохранность/атомарность, кадровый импорт, АвтоГраф, графики/полёты, календарь/балансы, редакции, Табель 2.0, SAP/ИСАТ, перенос «разукрашки», GTK, обновление приложения и инструкции.

## Первая партия — проверенные места

- `main.go:82-112`: запуск desktop отдельно от браузерного режима; запрещён второй desktop процесс при занятом 8779. Автоматическое завершение старого контроллера происходит в другом режиме; нельзя запускать несколько разных экземпляров с одним профилем.

Проверка устойчивости при внезапном отключении питания и `fsync` каталога после rename — отдельное исследование, не зарегистрированный баг.

### Обнаружено для дальнейшего исследования AG-AUDIT-002 (выбор вида графика)

`r11_core.go:436–473` (карточка) и L853–878 (`/api/autograf/schedule-change`) не выполняют проверку совместимости указанного `schedule_type` с `collection_point` по справочнику видов графиков. В интерфейсе `scheduleTypes(point)` фильтрует типы по пункту, но серверный вызов может сохранить произвольное название. **Это подтверждённый пробел серверной валидации, а не подтверждённый пользовательский сбой.** Нельзя без согласованного правила автоматически запретить исторические неизвестные типы: существующие тесты создают карточку с «A» без записи в справочнике. Разработать правило «если тип существует в справочнике для другого пункта — отвергать, если старый тип не известен ни в одном справочнике — сохранить совместимость», затем добавить API-тест и связанный ALT-тест из плана «АвтоГраф»; изменения карточек пользователей не делать без проверки регрессий.

### AUDIT-004 — размеры и распаковка XLSX (статический риск)

`xlsx.go:L112–132`: ZIP-XML читается через неограниченное `io.ReadAll`; L188–236 выделяет двумерный массив до максимальных номеров строки и колонки из XLSX без верхней границы. Повреждённая или злонамеренная книга может расходовать чрезмерную память. `r11_xlsx.go:L60–95` ограничивает чтение отдельных XML до 64 MiB, но не ограничивает число создаваемых колонок. **Ни одного пользовательского файла с этим сбоем не зафиксировано**; необходимо продумать лимиты, не мешающие крупным легитимным выгрузкам ИСАТ/SAP, и добавить синтетические тесты перед изменениями.
