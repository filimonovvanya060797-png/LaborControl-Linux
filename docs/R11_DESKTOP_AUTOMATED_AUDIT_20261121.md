# Техническая проверка LaborControl R11 Desktop — 21.11.2026

## Область проверки

Экспериментальная автономная настольная оболочка GTK3/WebKit2GTK + локальный R11 Linux Go Core. Проверки CI на Ubuntu, отдельная **синтетическая** база. Рабочие Windows R11, ALT Linux и данные водителей **не использовались**.

База: `feature/r11-native-desktop-gtk-20261121`. Исправления: `feature/r11-ui-smoke-audit-20261121` (draft PR #6). Не объединять с `main` без приёмки.

## Пройдено в GitHub Actions

- Настольная GTK/WebKit сборка, зависимости и `--check`; Windows cross-build Go: PASS.
- `go test -count=1 ./...`, `go vet`, `go test -race -count=1 ./...`, Linux smoke сервера: PASS.
- Node.js VM выполняет **реальный** JavaScript `r11_original.html` и открывает вкладки на синтетических состояниях: пустая база; водитель и план `1/8`; техническая версия; действующая/архивная официальные редакции (месяц и год); 450 водителей в двух колоннах: PASS.
- WebKitGTK (запущенный под Xvfb) загружает локальный Go Core, синтетического водителя, план `1/8`, техническую версию и официальную редакцию; последовательно открывает Главную, Сотрудников, РВД, Проверку табеля, События, Журнал, Инструкцию, Настройки, восемь вкладок АвтоГрафа и годовой режим: PASS.
- Сверка фронтенд-API с Go маршрутами: 39 используемых эндпоинтов обнаружены.
- Автотесты `r11_embedded_tab2_test.go` и `r11_tab2_plan_integration_test.go` проходят: встроенная вкладка Таб2 указывает на локальный сервер, её API видит план `1/8` из той же базы.

## Исправлено

1. Старое `iframe src="http://127.0.0.1:8767/?embed=tab2"` в `r11_original.html` ссылалось на другой порт. Заменено на `/tab2?embed=tab2`, дополнен локальный маршрут, Tab2 HTML и API теперь доступны на одном origin `127.0.0.1:8779`.
2. Добавлена защита CI от JavaScript ошибок отдельных экранов, включая WebKitGTK.
3. При ошибке UI теперь есть разворачиваемые **«Технические подробности для диагностики»** с HTML-экранированным stack trace. Это диагностика, **не** исправление первопричины.

## Не подтверждено — блокирующие пункты перед производственной работой

- **Найдена и исправлена конкретная причина `Can't find variable: v`:** `technicalVersionsPanel()` вызывал `versionPreview(v,e)` при выборе ранее сохранённой технической версии, хотя локальная переменная называется `view`. Исправлено на `versionPreview(view,e)`; добавлены отдельные smoke-тесты открытия и сравнения технической версии. Это дефект отображения, сохранённые данные не менялись. Проверка на ALT Linux после установки нового пакета ещё нужна.
- Полная функциональная эквивалентность исходного Windows R11, в том числе оригинальные алгоритмы Core, расчёт смен/циклов по реальным подтверждённым датам полётов, редакции, сверки SAP/ИСАТ и закрытие табеля: **не доказана**.
- Изолированный Linux Go Core является реализацией неполного подмножества Windows R11: существование кнопок/маршрутов не равно сохранению бизнес-правил.
- Отдельная Excel-«разукрашка» Windows ещё требует сравнения реальных форматов/правил импорта; совпадение раздела «Разукрашка / события» не доказывает эквивалентности Excel инструмента.
- Производительность измерялась как успешное **отображение** 450 сотрудников в Node VM, не как долгосрочная нагрузка на ALT Linux, память, импорты и полный год графика.
- GTK/WebKit CI основан на Ubuntu; на пользовательской ALT Linux после обновления нужна краткая проверка запуска и ошибок.
- Нужны негативные и интеграционные тесты реальных форматов: невалидные файлы, дубли, отмены, аварийное завершение, восстановление, перенос базы и неизменность плана при факте.

## Безопасный порядок дальнейшей работы

1. Не трогать установленную пользователем старую экспериментальную сборку, пока не согласовано обновление; отдельно сохранить копию его тестовой базы.
2. Загрузить новый ZIP из *успешного* Desktop CI и обновить **только** пользовательскую настольную установку; установщик не должен заменять существующую базу.
3. Повторить открытие/сравнение технической версии после исправления `v`, убедиться, что экран работает и планы остались без изменений. При иных ошибках раскрыть «Технические подробности».
4. После этого проводить практический полный цикл из `docs/R11_FULL_TEST_CYCLE.md` (в отдельной документационной ветке), поэтапно сравнивая с Windows R11 и Excel «разукрашкой».

**Текущий статус:** автоматическая CI-проверка экспериментальной сборки — зелёная; функциональная приёмка Windows R11 на ALT — **не завершена**.
