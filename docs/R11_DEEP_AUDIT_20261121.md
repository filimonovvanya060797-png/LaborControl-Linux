# LaborControl R11 на ALT Linux — углублённый аудит исходников, 21.11.2026

## Область и ограничения

Аудит охватывает доступный в приватном GitHub исходный код ветки `feature/r11-ui-smoke-audit-20261121` и внесённые здесь изменения: локальный Go Core, контроллер, Tab2, исходный HTML/JS R11, UI R9/Tab2, GTK/WebKitGTK desktop shell, CI и тесты. Исходный код оригинального Windows Core R11 **недоступен**: имеется бинарник и сведения об API, но это не база для доказательства идентичности бизнес-алгоритмов.

Ни один тест не обращается к реальной базе, SAP/ИСАТ в организации, штатному ALT Linux пользователю или личным данным. Выполняются синтетические Go/API и WebKitGTK тесты на GitHub Actions Ubuntu. Сборка устанавливается на ALT Linux отдельно.

### Как обнаруживались ошибки

- `go test -count=1 ./...`, `go vet ./...`, `go test -race -count=1 ./...`; настоящая Linux сборка и smoke сервера.
- Тест R11 JavaScript в VM с синтетическими сотрудниками/редакциями/версиями, 450 водителей; реальный WebKitGTK под Xvfb на localhost.
- Новый `R11 JavaScript static audit`: анализ обоих встроенных скриптов ESLint `no-undef`, `no-unreachable`, `no-dupe-args`, `valid-typeof`; намеренное переопределение legacy-функций исключено из правила `no-func-assign`, а не переписано слепо.
- Новые негативные API-тесты доказывают, что некорректный запрос отклоняется **без изменения базы**.

## Остающиеся существенные риски (не считать аудит полным доказательством готовности)

1. **Нет доказанной эквивалентности алгоритмам Windows Core R11.** Даты полётов, фазы, ДП, отпускные нормы, квартальный/годовой баланс, РВД, табели и история редакций требуют сравнения с эталонными результатами Windows R11 на обезличенных одинаковых входах.
2. **Excel-«разукрашка» Windows пока не перенесена и не сопоставлена с исходными макросами.** Видимая вкладка событий не равна полной функциональной замене.
3. **Tab2 импорты используют два JSON-файла.** В `tab2ImportFact` и `tab2ImportSAP` последовательные записи базы и хранилища Табеля 2.0 не образуют одну транзакцию: при сбое между записями возможна рассинхронизация. Нужна отдельная транзакционная переработка с тестами отказов.
4. **Массовое построение графика по дням выполняет множество отдельных `/api/day/quick-save`** и создаёт резервные копии на каждый день. Для 450 водителей и нескольких лет это риск задержек и заполнения диска. Нужен безопасный пакетный API с одним коммитом и одной резервной копией.
5. **JSON-хранилище каждый раз читает/пишет состояние целиком.** Отображение 450 водителей в JS-тесте не является нагрузочным испытанием 450×365/многолетней истории на ALT Linux; возможна миграция на транзакционную локальную БД только после сравнения данных.
6. **Форматы реальных ИСАТ/SAP/XLSX/CSV не исследованы на эталонных обезличенных наборах.** Парсер распознаёт часть форматов; необходимо тестировать дубли, пересечения, опоздания, больничные, служебные события, смешанные часовые поля, повреждённые книги и повторные загрузки.
7. **Совместимость со старой Windows/R9 установкой:** безопасная запись Linux поменялась; Windows кросс-сборка ≠ runtime-тест. Не обновлять Windows компонент этим черновиком.
8. **Изолированная тестовая ALT Linux установка:** требуется одно контрольное подтверждение запуска после нового пакета; текущие файлы пользователя не менялись.
9. **Права ранее созданных файлов:** новый код создаёт приватные файлы и бэкапы, но старые копии могут сохранять прежние права, пока не будут отдельно проверены/переписаны.
