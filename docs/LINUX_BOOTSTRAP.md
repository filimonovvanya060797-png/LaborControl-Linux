# Linux-bootstrap контроллера (пока не полная LaborControl R11)

Техническая адаптация **открытых исходников контроллера R9** под Linux. Оригинальные исходники в `archive/` не изменялись.

## Что проверено локально

В отдельной Linux-среде (не в VirtualBox пользователя), Go 1.23.2:

```sh
cd port/controller
CGO_ENABLED=0 go test ./...
CGO_ENABLED=0 go build -o /tmp/laborcontrol-controller .
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go test -c -o /tmp/laborcontrol-windows.test.exe
```

Все три команды завершились успешно. Последняя команда **компилирует** Windows-тесты, но не запускает их.

`CGO_ENABLED=0` помогает обойти ошибку `/usr/bin/x86_64-alt-linux-gcc: No such file or directory` при сборке чистого Go-кода на Альт Linux. Это не исправление CGO-зависимых компонентов.

### Изменения

- Платформенная реализация Linux: `xdg-open`, сообщения в stderr, XDG-папка данных и отдельное имя Core.
- Отказ от Windows-вызовов `rundll32`, `taskkill` и изменённого Windows PATH на Linux.
- Определение порта дочернего Core по файловым дескрипторам и `/proc`, без Windows `netstat`.
- Отдельные тесты для Linux и Windows; проверяется поиск порта собственного процесса.

### Что **пока не работает**

- Это порт **R9**, а не доказанная полная R11: действующий R11 содержит дополнительные правила смен и связи циклов полётов.
- Linux Core отсутствует. Исходников актуального Core v0.9.11 нет; интерфейс полностью не запустится до восстановления Core.
- Рабочую базу сотрудников не использовать. Тесты проводить только на синтетических данных.
- Проверка на Альт Linux 11.4 в VirtualBox пока не выполнена. GitHub Actions использует обычный Ubuntu runner, не виртуальную машину пользователя.
