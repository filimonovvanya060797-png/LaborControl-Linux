# LaborControl 1.0 — архитектура Проверки табеля R3

## Главный принцип

Текущий график LaborControl — единственный источник плана.

`АвтоГраф → Опер-табель ← Факт ИСАТ/SAP`

Далее:

`Опер-табель → Проверка выбранного дня`

и отдельно:

`Опер-табель + Факт + СЗ РВД → Сверка РВД`

## Интерфейс раздела

В «Проверке табеля» четыре рабочих подпункта:

- Опер-табель;
- Факт;
- Проверка;
- Сверка РВД.

Разукрашка и отдельная Проверка ДП отложены на следующий этап.

## Данные

Основная рабочая база остаётся `labor_control.json`.
Сырой факт, СЗ РВД и история импортов хранятся в `labor_control_tab2.json`.
Рабочая база пользователя не включается в релиз.

## Автообновление

`/api/tab2/state` перечитывает текущую основную базу. Пока открыт раздел,
интерфейс проверяет изменение файлов каждые 5 секунд. Поэтому изменение плана
в АвтоГрафе отражается в Опер-табеле без отдельной синхронизации.

## Совместимость

Существующий backend v0.9.11 остаётся внутренним `LaborControl_Core.exe`.
Новый контроллер предоставляет новый UI/API и не требует изменения схемы старого Core.
