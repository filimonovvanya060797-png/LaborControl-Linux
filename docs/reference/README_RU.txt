Новый Табель 2.0 теперь встроен прямо в ту страницу LaborControl, которая реально открывается Core.

LaborControl 1.0 — TIMESHEET PREVIEW R11
==============================================

Это предварительная сборка следующего большого блока LaborControl.
АвтоГраф и ранее проверенная логика сохранены без повторного переписывания.
Фокус R11 — «Проверка табеля» плюс исправление привязки видов графиков к отдельным циклам полётов.

ЗАПУСК
------
1. Распаковать ZIP целиком в отдельную папку.
2. Запустить только LaborControl.exe.
3. LaborControl_Core_R11.exe запускается автоматически.

ВАЖНО ПРО БАЗУ
--------------
Рабочая база labor_control.json НЕ входит в ZIP и не заменяется.
Используется существующая база:
  %LOCALAPPDATA%\LaborControl\labor_control.json

Дополнительные данные Проверки табеля (сырой факт, СЗ РВД, история импортов)
хранятся отдельно:
  %LOCALAPPDATA%\LaborControl\labor_control_tab2.json

ЧТО СЕЙЧАС В «ПРОВЕРКЕ ТАБЕЛЯ»
--------------------------------
Внутри раздела четыре подпункта:

1. ОПЕР-ТАБЕЛЬ
   Перенос рабочего листа «план_факт»:
   - Табель;
   - ФИО;
   - 5 строк на сотрудника:
       план
       смена свод
       факт
       смена исат
       вывод
   - дни 1–31 по горизонтали.

   Строка «план» не копируется отдельно: она каждый раз читается из текущего
   графика LaborControl. Изменение АвтоГрафа автоматически отражается в Опер-табеле.

2. ФАКТ
   Можно загрузить XLSX/XLSM/CSV или вставить строки из Excel/ИСАТ.
   Для путевых листов используются:
   Табель, ФИО, Путевой лист с, Путевой лист по, Часов отработано.
   День и время вычисляются автоматически.
   По макросу исходной книги смена определяется так:
   06:00–09:59 = день;
   18:00–22:59 = ночь;
   остальное = смена не определена.

   Загруженный факт попадает одновременно в Опер-табель и в ячейки графика сотрудника.

3. ПРОВЕРКА
   Выбирается одна дата. Проверяются все сотрудники Опер-табеля.
   Показываются:
   - нет факта при рабочем плане;
   - плановые и фактические часы не совпадают;
   - смена свод и смена исат не совпадают;
   - при факте отсутствует смена свод;
   - при факте не определилась смена исат.

4. СВЕРКА РВД
   Загружается актуальный Excel СЗ РВД.
   Кандидат на РВД определяется как:
     в плане стоит В или ДП + фактически отработано больше 0 часов.

   Затем программа сверяет кандидатов с СЗ РВД и показывает:
   - Нет в СЗ;
   - Нет подтверждения;
   - Частично;
   - Вне СЗ;
   - Лишний;
   - Расхождение;
   - OK;
   - Отгулы.

   Для РВД-1 дополнительно сравнивается количество дней РВД и период отгула.

ЧТО НЕ ВХОДИТ В ТЕКУЩИЙ ФОКУС
------------------------------
Разукрашка и отдельная Проверка ДП пока не являются предметом R11.
Их кодовые заготовки не используются в интерфейсе «Проверка табеля» и будут
доводиться следующим этапом.

АВТОГРАФ
--------
Ранее проверенный АвтоГраф не тестируем заново. В R11 дополнительно исправлена связь вида графика с конкретным циклом полётов; связь Опер-табеля остаётся такой:
если план в графике изменился, Опер-табель должен увидеть новое значение.

СТАТУС
------
R11 — рабочий preview с исправлением циклов полётов и текущим модулем «Проверка табеля».

R9 — исправление запуска
-----------------------
В R9 внутренний Core имел уникальное имя LaborControl_Core_R9.exe, поэтому он не может случайно остаться старым файлом от предыдущей распаковки.
Старый Core больше не открывает собственную страницу: локальный shim/rundll32.exe подавляет только его автоматический вызов браузера. Сам Core и его HTTP API работают обычно.
Пользователю открывается только оболочка R9 по адресу http://127.0.0.1:8779/ .
На ней версия отображалась как v1.0 TIMESHEET R9, а внутри «Проверка табеля» — вкладки «Опер-табель», «Факт», «Проверка», «Сверка РВД».


R11 — привязка вида графика к конкретному циклу полётов
--------------------------------------------------------
Причина исправления: при наличии нескольких циклов одного пункта сбора Конструктор R9 объединял все даты этого пункта, поэтому ДП из двух независимых циклов попадали в один график сотрудника.

В R11:
- каждый вид графика имеет поле «Цикл полётов»;
- вид с точкой и без точки могут быть парой, но каждый привязывается к своему циклу;
- Конструктор использует только даты выбранного цикла;
- если у пункта несколько циклов, а вид графика не привязан ни к одному, построение блокируется с понятным сообщением;
- массовая проверка индивидуальных полётов также проверяет соответствие конкретному циклу вида графика.

Для уже созданных видов Сургута откройте «Виды графиков» → «Изменить» и выберите нужный цикл отдельно для «Сур-Тал-Сур 11» и «Сур-Тал-Сур 11.».

R11 — правило «смена свод» в Опер-табеле
----------------------------------------
Смена плана определяется из значения АвтоГрафа:
- 11, 10, 9 и другие положительные числовые часы -> день;
- 1/11, 1/10, 1/9 и аналогичные 1/N -> день;
- 2/11, 2/10, 2/9 и аналогичные 2/N -> ночь;
- В, ДП, ОТ, 0 и пусто -> смена не задаётся.
