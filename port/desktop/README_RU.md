# LaborControl R11 — экспериментальное отдельное окно для ALT Linux

Это GTK3 + WebKit2GTK 4.1 приложение без вкладок/адресной строки Chromium. Оно отображает встроенный оригинальный интерфейс R11, сохраняя работающий Go-контроллер. HTML/HTTP API и JSON-формат остаются прежними. Интернет не требуется.

**Внимание:** это экспериментальная оболочка; правильность расчётов АвтоГрафа, Табеля 2.0 и «разукрашки» ещё не подтверждена сравнением с Windows R11.

## Установка и запуск

1. В GitHub Actions скачать артефакт **laborcontrol-r11-gtk-desktop-amd64-experimental** и полностью распаковать его.
2. В одной папке должны оказаться: laborcontrol-desktop, laborcontrol-controller, laborcontrol.svg, install-user.sh и README_RU.md.
3. Если исполнительные биты отсутствуют после ZIP: `chmod +x laborcontrol-desktop laborcontrol-controller install-user.sh`.
4. Закрыть все старые запуски LaborControl на порту 8779. Новая оболочка не завершает чужой сервер и не подключается к нему.
5. Запустить `./laborcontrol-desktop`. Чтобы добавить пункт меню, один раз выполнить `./install-user.sh` (не нужен sudo).

Для работы нужны системные библиотеки GTK3 и WebKit2GTK 4.1. На ALT Linux проверить их наличие в целевой VM — успешная сборка Ubuntu ещё не гарантирует совместимости ABI на ALT. Приложение можно также собрать прямо на ALT: `bash port/desktop/build.sh`, если установлены gcc, pkg-config, GTK3/WebKitGTK development-пакеты и Go.

Путь тестовых данных по умолчанию: `~/.local/share/LaborControl-R11-Desktop-Experimental/LaborControl/`. Он отдельный от прежней экспериментальной браузерной версии и рабочей Windows-базы. Можно изменить только через абсолютный путь в `LABORCONTROL_DESKTOP_DATA_HOME`.

## Принцип работы и безопасность

- Настольная оболочка запускает Go-процесс с `LABORCONTROL_DESKTOP_MODE=1`, предотвращая открытие Chromium.
- Оболочка проверяет, что порт свободен, и ждёт HTTP /health **с собственным токеном экземпляра**, прежде чем отобразить R11.
- Запрашивается только локальный адрес `127.0.0.1:8779/r11`; внешние ссылки выводятся отдельно и не заменяют окно LaborControl.
- При закрытии окна отправляется штатный `POST /api/shutdown`. Данные пишутся через существующий серверный механизм.
- Внутри используется webview (WebKit), а не полностью переписанные нативные формы. Это позволяет не терять внешний вид и функциональные соглашения R11.

## Проверки перед использованием на ALT

Проверить: `./laborcontrol-desktop --check`, отдельное окно без вкладок, пункт меню, создание только вымышленных сотрудников, запись дня и повторное открытие, корректное закрытие, поведение при занятом порте и недоступных библиотеках. **Рабочие базы и файлы ИСАТ/SAP не импортировать**.
